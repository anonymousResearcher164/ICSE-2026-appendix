
The robot starts by trying to reach its goal. It plans a route using the GridBased planner, smoothens it, and follows it with the FollowPath controller. A RateController set to 0.02 Hz regulates planning, while a DistanceController set to 2.0 metres regulates smoothing. If something goes wrong, the robot first tries to recover from the specific problem. When planning fails, it checks whether the goal has changed. If not, it clears the global costmap and tries planning again. Smoothing follows a similar process, but its recovery also includes calculating a fresh route before trying to smooth it again. Both stages allow one retry. If the robot has trouble following the path, it checks for a changed goal or clears the local costmap before another attempt. If these smaller recovery steps are not enough, NavigateRecovery moves to the broader recovery branch. This contains a goal-update check and a RoundRobin called RecoveryActions, which takes turns trying different options like clearing the local and global costmaps, waiting five seconds, or backing up 0.15 metres at 0.025 metres per second. A successful recovery gives the robot another chance to navigate, with up to six recovery-and-retry cycles allowed overall. The tree succeeds when the main navigation branch succeeds. It fails if recovery fails or the available retries are used up.
