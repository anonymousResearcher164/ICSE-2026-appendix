The mission describes navigation to a goal, path planning, path following, and recovery actions for failed
navigation.

First, the root RecoveryNode NavigateRecovery will execute the main navigation behavior. If the main navigation
behavior fails, it will execute the recovery behavior and retry the main navigation behavior. It will stop
execution when recovery retries are exhausted.

Next, the PipelineSequence NavigateWithReplanning will execute the path-planning and path-following behaviors in
order. While either behavior is running or has succeeded, it will proceed to the next behavior. It will stop the
sequence if a behavior fails.

Then, the RateController will regulate the execution of the ComputePathToPose recovery behavior. The nested
RecoveryNode ComputePathToPose will execute path computation. If path computation fails, it will clear the global
costmap and retry path computation.

Next, the RecoveryNode FollowPath will execute path following. If path following fails, it will clear the local
costmap and retry path following.

Finally, the ReactiveFallback RecoveryFallback will execute the GoalUpdated behavior first. If GoalUpdated
succeeds, it will stop the recovery fallback. If GoalUpdated fails, it will execute the RecoveryActions sequence.
While the recovery actions are running, it will re-evaluate GoalUpdated and stop the recovery actions if
GoalUpdated succeeds.

Next, the SequenceStar RecoveryActions will clear the local costmap, clear the global costmap, spin, and wait in
order. If an action succeeds, it will remember that action and move to the next action. If an action fails, it will
restart the sequence from the failed action.

Parameters: ComputePathToPose will use goal read from the goal key, store the resulting path under the path key,
and use the literal planner ID GridBased.

ClearGlobalCostmap-Context will use the literal service name global_costmap/clear_entirely_global_costmap.

FollowPath will use the path read from the path key and the literal controller ID FollowPath.

ClearLocalCostmap-Context will use the literal service name local_costmap/clear_entirely_local_costmap.

ClearLocalCostmap-Subtree will use the literal service name local_costmap/clear_entirely_local_costmap.

ClearGlobalCostmap-Subtree will use the literal service name global_costmap/clear_entirely_global_costmap.

Spin will use the literal spin distance 1.57.

Wait will use the literal wait duration 5.
