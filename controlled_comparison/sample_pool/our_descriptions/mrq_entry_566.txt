The mission describes repeated locomotion planning, replanning, movement, and temporal-logic state updates.

First, the robot will execute the sequence for the number of cycles stored under num_cycles.

Next, it will execute the first fallback. It will execute custom action LTLPreCheck with ltl_state_current read
from ltl_state_current and ltl_state_desired_sequence read from ltl_state_desired_sequence. If LTLPreCheck will
fail, it will execute ForceFailure with custom action ReplanningRequestLevel2 and make sure that action always
fails. The fallback will fail if no action will succeed.

Next, it will execute the reactive sequence. It will execute the first fallback in the reactive sequence. It will
repeatedly try the nested fallback until it will succeed. The nested fallback will first execute custom action
LocomotionStatusCheck with locomotion_status read from locomotion_status. If that action will fail, it will
execute the sequence that follows. The sequence will execute custom action RecoveryStand with locomotion_status
read from locomotion_status. It will then wait for 5000 milliseconds before executing custom action
LocomotionStart with locomotion_status read from locomotion_status. If all attempts will fail, it will execute
ForceFailure with custom action ReplanningRequestLevel3 and make sure that action always fails.

Next, while the reactive sequence will execute its later actions, it will re-evaluate the earlier actions. If an
earlier action will fail, it will halt the running action and stop the reactive sequence.

Next, it will execute the second fallback in the reactive sequence. It will execute custom action MoveAction. If
MoveAction will fail, it will execute ForceFailure with custom action ReplanningRequestLevel3 and make sure that
action always fails. The fallback will fail if neither action will succeed.

Finally, it will execute custom action UpdateLTL.

Parameters: MoveAction will use action stored under action, move_base_finished read from move_base_finished,
move_base_idle read from move_base_idle, and nav_goal read from nav_goal. UpdateLTL will use action_sequence
stored under action_sequence, ltl_state_desired_sequence stored under ltl_state_desired_sequence, and will store
its navigation goal under nav_goal.
