The mission describes a repeated navigation behavior that checks the current logical state, maintains locomotion,
moves toward a navigation goal, and updates the logical state.

First, the robot will execute the root repeat node for the number of cycles specified by {num_cycles}.

Next, it will execute the sequence in order and stop the sequence if any action fails.

Next, it will execute the first fallback consecutively. If LTLPreCheck fails, it will execute
ReplanningRequestLevel2 through ForceFailure, and that branch will always fail.

Next, it will execute the reactive sequence. It will execute its child fallbacks in order and stop if an action
fails. While a later action is running, it will re-evaluate the preceding actions and stop the running action if a
preceding action fails.

Next, it will execute the retry-until-successful decorator. It will repeatedly execute the enclosed fallback until
that fallback succeeds.

Next, it will execute the enclosed fallback consecutively. It will first execute LocomotionStatusCheck. If
LocomotionStatusCheck fails, it will execute the sequence that runs RecoveryStand and then delays LocomotionStart
for the specified delay. If the sequence fails, the fallback will finish unsuccessfully.

Next, it will execute the second fallback consecutively. It will first execute MoveAction. If MoveAction fails, it
will execute ReplanningRequestLevel3 through ForceFailure, and that branch will always fail.

Next, it will execute UpdateLTL after the reactive sequence succeeds.

Parameters: LTLPreCheck will read {ltl_state_current} and {ltl_state_desired_sequence}. ReplanningRequestLevel2
will read and update {replanning_request}. LocomotionStatusCheck will read {locomotion_status}. RecoveryStand will
read {locomotion_status}. Delay will use a delay of 5000 milliseconds. LocomotionStart will read
{locomotion_status}. ReplanningRequestLevel3 will read and update {replanning_request}. MoveAction will store its
action in {action}, read {move_base_finished}, read {move_base_idle}, and read {nav_goal}. UpdateLTL will read and
update {action_sequence}, read and update {ltl_state_desired_sequence}, and store the navigation goal in
{nav_goal}.
