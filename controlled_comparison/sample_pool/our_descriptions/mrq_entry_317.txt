The mission describes navigation to a goal with path planning, path following, replanning, and recovery actions.

First, the robot will execute the NavigateWithReplanning pipeline. If the pipeline fails, it will execute the
RecoveryFallback recovery action and retry the pipeline for up to six retries.

Next, it will execute the ComputePathToPose recovery node at a rate of 1.0 Hz and then execute the FollowPath
recovery node. The pipeline will advance to the next node while the current node is running or has succeeded, and
it will stop if a node fails.

Next, it will execute the ComputePathToPose action. If this action fails, it will execute the
ComputePathToPoseRecoveryFallback recovery action and retry the ComputePathToPose action once.

Next, it will execute the ComputePathToPoseRecoveryFallback reactive fallback. If GoalUpdated succeeds, it will
stop the fallback. If GoalUpdated fails, it will clear the global costmap.

Next, it will execute the FollowPath action. If this action fails, it will execute the FollowPathRecoveryFallback
recovery action and retry the FollowPath action once.

Next, it will execute the FollowPathRecoveryFallback reactive fallback. If GoalUpdated succeeds, it will stop the
fallback. If GoalUpdated fails, it will clear the local costmap.

Next, it will execute the RecoveryFallback reactive fallback. If GoalUpdated succeeds, it will stop the fallback.
If GoalUpdated fails, it will execute the RecoveryActions recovery sequence.

Next, it will execute the RecoveryActions recovery actions in turn. It will first execute the ClearingActions
sequence, then spin, then wait, and then back up.

Next, it will execute the ClearingActions sequence in order. It will clear the local costmap and then clear the
global costmap, and it will stop the sequence if either action fails.

Parameters: The ComputePathToPose action will read the goal from {goal}, store the computed path under {path}, and
use the literal planner identifier GridBased.
