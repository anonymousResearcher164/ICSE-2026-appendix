The mission describes the robot's behavior for selecting and planning a requested driving maneuver or following
its lane.

First, the Fallback will execute the first ReactiveSequence, the second ReactiveSequence, the third
ReactiveSequence, the fourth ReactiveSequence, the fifth ReactiveSequence, and the custom action
LaneFollowing_Plan consecutively. If a child fails, it will move to the next child until one succeeds. If no child
succeeds, the execution will fail.

Next, the first ReactiveSequence will execute the PullOver_Request condition, the PullOver_Ready condition, and
the custom action PullOver_Plan in sequence. If a condition or action fails, it will stop the sequence. While an
action is running, it will re-evaluate the preceding conditions, halt the running action if a preceding condition
fails, and stop the sequence. The custom action PullOver_Plan will store its result under output.

Then, the second ReactiveSequence will execute the PullOut_Request condition, the PullOut_Ready condition, and the
custom action PullOut_Plan in sequence. If a condition or action fails, it will stop the sequence. While an action
is running, it will re-evaluate the preceding conditions, halt the running action if a preceding condition fails,
and stop the sequence. The custom action PullOut_Plan will store its result under output.

Next, the third ReactiveSequence will execute the SideShift_Request condition, the SideShift_Ready condition, and
the custom action SideShift_Plan in sequence. If a condition or action fails, it will stop the sequence. While an
action is running, it will re-evaluate the preceding conditions, halt the running action if a preceding condition
fails, and stop the sequence. The custom action SideShift_Plan will store its result under output.

Then, the fourth ReactiveSequence will execute the LaneChange_Request condition, the nested Fallback, and the
custom action LaneChange_Plan in sequence. If a condition or action fails, it will stop the sequence. While an
action is running, it will re-evaluate the preceding conditions, halt the running action if a preceding condition
fails, and stop the sequence. The custom action LaneChange_Plan will store its result under output.

Next, the nested Fallback will execute the LaneChange_Ready condition and the ForceLaneChange_ForceApproval
condition consecutively. If the LaneChange_Ready condition fails, it will execute the
ForceLaneChange_ForceApproval condition. If either condition succeeds, the nested fallback will succeed. If both
conditions fail, the nested fallback will fail.

Then, the fifth ReactiveSequence will execute the Avoidance_Request condition, the Avoidance_Ready condition, and
the custom action Avoidance_Plan in sequence. If a condition or action fails, it will stop the sequence. While an
action is running, it will re-evaluate the preceding conditions, halt the running action if a preceding condition
fails, and stop the sequence. The custom action Avoidance_Plan will store its result under output.

Finally, the custom action LaneFollowing_Plan will execute as the final fallback option and will store its result
under output.
