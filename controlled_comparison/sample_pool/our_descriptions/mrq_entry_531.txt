The mission describes recovery-based navigation to a goal, including path planning, path smoothing, path
following, progress monitoring, and recovery actions.

First, the root RecoveryNode will execute the main ResetterNode action. If the main action fails, it will execute
the recovery action and retry the main action up to six times. If recovery fails after the retries are exhausted,
the mission will stop.

Next, the ResetterNode will execute the GoalUpdated condition and the NavigateWithReplanning action.

Then, the GoalUpdated condition will determine whether the navigation goal has been updated.

Next, the NavigateWithReplanning action will execute the ComputePathToPose recovery node at a rate of 0.02 hertz.
It will then execute the SmoothPath recovery node when the distance condition is satisfied for a distance of 2.0.
It will then execute the FollowPath recovery node and the HadFeedback_FollowPath action in sequence. If any action
fails, the pipeline will stop. While an action is running or has succeeded, it will continue to the next action.

Then, the ComputePathToPose recovery node will execute the ComputePathToPose action. If that action fails, it will
execute the ComputePathToPoseRecoveryFallback recovery action and retry the main action once.

Next, the ComputePathToPoseRecoveryFallback reactive fallback will execute the GoalUpdated condition and the
ClearGlobalCostmap-Context action in order. If the GoalUpdated condition succeeds, it will stop. Otherwise, it
will execute the ClearGlobalCostmap-Context action. While that action is running, it will re-evaluate the
GoalUpdated condition and stop if the condition succeeds.

Then, the SmoothPath recovery node will execute the SmoothPath action. If that action fails, it will execute the
SmoothPathRecoveryFallback recovery action and retry the main action once.

Next, the SmoothPathRecoveryFallback reactive fallback will execute the GoalUpdated condition and the recovery
sequence in order. If the GoalUpdated condition succeeds, it will stop. Otherwise, it will clear the global
costmap and compute a new path. While the recovery sequence is running, it will re-evaluate the GoalUpdated
condition and stop if the condition succeeds.

Then, the recovery sequence will execute the ClearGlobalCostmapSmoother-Context action and the ComputePathToPose
action in order. It will stop if either action fails.

Next, the FollowPath recovery node will execute the FollowPath action. If that action fails, it will execute the
FollowPathRecoveryFallback recovery action and retry the main action once.

Then, the FollowPathRecoveryFallback reactive fallback will execute the GoalUpdated condition and the
ClearLocalCostmap-Context action in order. If the GoalUpdated condition succeeds, it will stop. Otherwise, it will
clear the local costmap. While that action is running, it will re-evaluate the GoalUpdated condition and stop if
the condition succeeds.

Next, the HadFeedback_FollowPath action will verify that feedback has been received during path following.

Then, the root RecoveryNode will execute the RecoveryFallback reactive fallback when the ResetterNode action
fails. If the GoalUpdated condition succeeds, it will stop the recovery fallback. Otherwise, it will execute the
RecoveryActions round-robin action. While a recovery action is running, it will re-evaluate the GoalUpdated
condition and stop if the condition succeeds.

Finally, the RecoveryActions round-robin action will execute the ClearingActions sequence, the Wait action, and
the BackUp action in rotation.

Next, the ClearingActions sequence will clear the local costmap and then clear the global costmap. It will stop if
either clearing action fails.

Then, the Wait action will wait for five seconds.

Finally, the BackUp action will move backward by 0.15 meters at a speed of 0.025 meters per second.

Parameters: The ComputePathToPose action will read the goal from {goal}, store the coarse path under
{path_coarse}, and use the GridBased planner. The SmoothPath action will read the path from {path_coarse}, store
the smoothed path under {path}, and use the SmoothPath smoother.
