The mission describes navigation to a goal with path planning, path smoothing, path following, feedback monitoring,
and recovery actions.

First, the robot will execute the main ResetterNode action. If it fails, it will execute the RecoveryFallback
action, retry the main action, and stop after six recovery attempts are exhausted.

Next, ResetterNode will execute the GoalUpdated condition and the NavigateWithReplanning subtree in order.

Then, NavigateWithReplanning will execute the RateController, DistanceController, FollowPath recovery subtree, and
HadFeedback condition in order. It will proceed to the next child while the current child is running or has
succeeded, and it will stop if a child fails.

Next, RateController will execute the ComputePathToPose recovery subtree at the configured rate. ComputePathToPose
will calculate a coarse path. If it fails, ComputePathToPoseRecoveryFallback will check whether the goal has been
updated. If the goal has not been updated, it will clear the global costmap. The recovery will retry
ComputePathToPose once after recovery.

Then, DistanceController will execute the SmoothPath recovery subtree after the configured distance condition is
met. SmoothPath will smooth the coarse path. If it fails, SmoothPathRecoveryFallback will check whether the goal
has been updated. If the goal has not been updated, it will clear the global costmap and calculate a new coarse
path in sequence. The recovery will retry SmoothPath once after recovery.

Next, the FollowPath recovery subtree will follow the smoothed path. If it fails, FollowPathRecoveryFallback will
check whether the goal has been updated. If the goal has not been updated, it will clear the local costmap. The
recovery will retry FollowPath once after recovery.

Then, the outer RecoveryFallback will check whether the goal has been updated after the main navigation action
fails. If the goal has not been updated, it will execute the RecoveryActions round-robin subtree.

Next, RecoveryActions will execute ClearingActions, Wait, and BackUp in rotation. ClearingActions will clear the
local costmap and then the global costmap in sequence. Wait will pause for the configured duration. BackUp will
move the robot backward for the configured distance.

Parameters: ComputePathToPose will receive goal from {goal}, store its output under {path_coarse}, and use the
planner ID GridBased. ClearGlobalCostmap-Context will use the service global_costmap/clear_entirely_global_costmap.
SmoothPath will receive the input path from {path_coarse}, store its output under {path}, and use the smoother ID
SmoothPath. ClearGlobalCostmapSmoother-Context will use the service global_costmap/clear_entirely_global_costmap.
ComputePathToPose will receive goal from {goal}, store its output under {path_coarse}, and use the planner ID
GridBased. FollowPath will receive the path from {path} and use the controller ID FollowPath.
ClearLocalCostmap-Context will use the service local_costmap/clear_entirely_local_costmap.
ClearLocalCostmap-Subtree will use the service local_costmap/clear_entirely_local_costmap.
ClearGlobalCostmap-Subtree will use the service global_costmap/clear_entirely_global_costmap. Wait will use a wait
duration of 5. BackUp will use a backup distance of 0.15 and a backup speed of 0.025. RateController will use a
frequency of 0.02 hertz. DistanceController will use a distance of 2.0. NavigateRecovery will allow 6 recovery
attempts. ComputePathToPose will allow 1 recovery retry. SmoothPath will allow 1 recovery retry. FollowPath will
allow 1 recovery retry.
