The mission describes autonomous road navigation with lane keeping, lane changes, traffic-light handling,
unprotected-turn handling, path generation, and mission-state publication.

The root fallback Core_seq will consecutively execute the first sequence and the second sequence until one
sequence succeeds. If the first sequence succeeds, execution will stop. If the first sequence fails, the second
sequence will execute.

First, the first sequence will check whether checkMissionWait is true and will execute stop if the condition
succeeds. If checkMissionWait is false, this sequence will fail.

Next, the second sequence will execute init and the gen path sequence before it will set the path, publish data,
and process the mission state.

First, the init sequence will check whether checkExistPathGlobal is true. It will then execute the nested fallback
and init. The sequence will stop if an action fails.

Next, the nested fallback will first execute a sequence that checks whether checkStateLaneKeeping is true, checks
whether checkFailLaneChange is true, and executes callPathGlobal. If that sequence fails, the fallback will
execute AlwaysSuccess.

Next, the gen path sequence will execute the StateSelect fallback, the traffic check fallback, and the
unprotectedTurn fallback in order. It will stop if a child fails.

First, the StateSelect fallback will evaluate LaneKeeping, LaneChangeLeft, LaneChangeRigth, and Recovery in order.
If one child succeeds, it will stop evaluating the remaining children. If all children fail, the fallback will
fail.

Next, the LaneKeeping sequence will check whether checkStateLaneKeeping is true and will execute
genPathLaneKeeping, the nested LaneKeeping sequence, and the must-lane-change fallback in order.

First, the nested LaneKeeping sequence will execute the lane-change evaluation fallback and the must-lane-change
fallback in order.

Next, the lane-change evaluation fallback will first evaluate the global lane-change sequence. If that sequence
fails, it will evaluate the check Collision sequence. If that sequence also fails, it will execute
setStateLaneKeeping.

First, the global lane-change sequence will check whether checkGlobalLaneChange is true. It will then evaluate the
left-change sequence, the right-change sequence, and setStateLaneKeeping.

Next, the left-change sequence will check whether checkLeftChange is true. It will then evaluate the left
lane-change sequence and setStateLaneKeeping.

Next, the left lane-change sequence will check whether checkLaneChangeableLeft is true and will execute
genPathLaneChangeLeft. It will then evaluate whether the left lane remains blocked or safe.

Next, the left-lane safety fallback will first evaluate a sequence that checks whether checkObjectStaticLeftLane
is true or checkCollisionBehindLeft is true and then executes setStateLaneKeeping. If that sequence fails, it will
execute setStateLaneChangeLeft.

Next, the right lane-change sequence will check whether checkLaneChangeableRight is true and will execute
genPathLaneChangeRight. It will then evaluate whether the right lane remains blocked or safe.

Next, the right-lane safety fallback will first evaluate a sequence that checks whether checkObjectStaticRightLane
is true or checkCollisionBehindRight is true and then executes setStateLaneKeeping. If that sequence fails, it
will execute setStateLaneChangeRight.

Next, the check Collision sequence will check whether checkFrontObject is true. It will then evaluate the
lane_keeping fallback and the lane_change fallback.

First, the lane_keeping fallback will evaluate the inverted checkIrregularFront condition and will then evaluate
checkNearCorner, checkObjectNearGoal, and checkMeNearGoal. If one condition succeeds, the fallback will stop.

Next, the lane-keeping response sequence will execute setStateLaneKeeping after the preceding fallback succeeds.

Next, the lane_change fallback will evaluate the left lane-change sequence and the right lane-change sequence in
order. If both alternatives fail, it will execute setStateLaneKeeping.

First, the left lane-change sequence will check whether checkProfitLaneChangeLeft is true. It will then evaluate
the left-lane safety sequence and the left lane-change execution sequence before it will execute
setStateLaneKeeping.

Next, the right lane-change sequence will check whether checkProfitLaneChangeRight is true. It will then evaluate
the right-lane safety sequence and the right lane-change execution sequence before it will execute
setStateLaneKeeping.

Next, the must-lane-change fallback will check whether checkMustLaneChange is true. If the condition is false, it
will execute AlwaysSuccess.

Next, the LaneChangeLeft sequence will check whether checkStateLaneChangeLeft is true. It will then evaluate the
lane-change completion fallback.

Next, the lane-change completion fallback will first evaluate a sequence that checks whether checkEndLaneChange is
true, executes setStateLaneKeeping, and executes callPathGlobal. If that sequence fails, it will execute
speedProfileLaneChange.

Next, the LaneChangeRigth sequence will check whether checkStateLaneChangeRight is true. It will then evaluate the
lane-change completion fallback.

Next, the lane-change completion fallback will first evaluate a sequence that checks whether checkEndLaneChange is
true, executes setStateLaneKeeping, and executes callPathGlobal. If that sequence fails, it will execute
speedProfileLaneChange.

Next, the Recovery sequence will execute setStateLaneKeeping.

Next, the traffic check fallback will check whether checkPassAbleTrafficLight is true. If the condition is false,
it will execute stopTrafficLight.

Next, the unprotectedTurn fallback will first evaluate a sequence that checks whether checkUnprotected is true,
checks whether checkImpassalbeUnprotected is true, and executes stop. If that sequence fails, it will execute
AlwaysSuccess.

Next, the mission-state fallback will first evaluate a sequence that checks whether checkArriveGoal is true,
executes setStateMissionArrive, and executes publishStateMission. If that sequence fails, it will execute a
sequence that runs setStateMissionGoing.
