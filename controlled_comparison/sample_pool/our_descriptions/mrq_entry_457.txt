The mission describes a vehicle mission that manages waiting, path initialization, lane keeping, lane changes,
traffic lights, unprotected turns, path execution, data publication, and mission-state publication.

First, the robot will execute the Core_seq fallback. If the mission-wait condition succeeds, it will execute the
stop action. If that sequence fails, it will execute the main mission sequence. If neither sequence succeeds, the
fallback will fail.

Next, the main mission sequence will execute the initialization, path-setting, data-publication, and mission-state
actions in order. The sequence will stop if any action fails.

Then, the initialization sequence will check whether a global path exists. If no global path exists, it will
execute the nested fallback. That fallback will try to confirm lane-keeping mode, confirm that a lane-change
failure is absent, and call the global-path action. If that sequence fails, the AlwaysSuccess node will succeed.
The initialization sequence will then execute the init action. It will next execute the path-generation sequence.

Next, the path-generation sequence will execute the StateSelect fallback, the traffic-check fallback, and the
unprotected-turn fallback in order. The sequence will stop if any fallback fails.

Then, the StateSelect fallback will try the LaneKeeping sequence. If that sequence fails, it will try the
LaneChangeLeft sequence. If that sequence fails, it will try the LaneChangeRigth sequence. If that sequence fails,
it will execute the Recovery sequence.

Next, the LaneKeeping sequence will check whether lane-keeping mode is active. If the condition succeeds, it will
generate a lane-keeping path. It will then execute the nested LaneKeeping sequence. It will stop if any action or
condition fails.

Then, the nested LaneKeeping sequence will execute the lane-selection fallback and the mandatory-lane-change
fallback in order. The sequence will stop if either fallback fails.

Next, the lane-selection fallback will try the global-lane-change sequence. If that sequence fails, it will try
the collision-check sequence. If that sequence fails, it will execute the setStateLaneKeeping action.

Then, the global-lane-change sequence will check whether a global lane change is required. If the condition
succeeds, it will execute the left-change fallback and the right-change sequence in order. The sequence will stop
if any child fails.

Next, the left-change fallback will try the left-change sequence. If that sequence fails, it will execute the
setStateLaneKeeping action.

Then, the left-change sequence will check whether a left lane change is requested. If the condition succeeds, it
will execute the left-lane-change preparation sequence. The sequence will stop if any child fails.

Next, the left-lane-change preparation sequence will check whether the left lane is changeable. It will then
generate a left lane-change path. It will next execute the left-lane safety fallback. The sequence will stop if
any child fails.

Then, the left-lane safety fallback will try the left-lane safety sequence. If that sequence fails, it will
execute the setStateLaneChangeLeft action.

Next, the left-lane safety sequence will execute the fallback that checks for a static object in the left lane or
a collision behind the left side. It will then execute the setStateLaneKeeping action. The sequence will stop if
any child fails.

Then, the right-change sequence will check whether the right lane is changeable. It will then generate a right
lane-change path. It will next execute the right-lane safety fallback. The sequence will stop if any child fails.

Next, the right-lane safety fallback will try the right-lane safety sequence. If that sequence fails, it will
execute the setStateLaneChangeRight action.

Then, the right-lane safety sequence will execute the fallback that checks for a static object in the right lane
or a collision behind the right side. It will then execute the setStateLaneKeeping action. The sequence will stop
if any child fails.

Next, the collision-check sequence will check whether an object is in front. If the condition succeeds, it will
execute the front-object fallback. The sequence will stop if any child fails.

Then, the front-object fallback will try the lane-keeping sequence. If that sequence fails, it will try the
lane-change fallback. If that fallback fails, it will execute the setStateLaneKeeping action.

Next, the front-object lane-keeping sequence will execute the inverted irregular-front condition. The inverted
condition will succeed when the irregular-front condition fails. It will then execute the fallback that checks
whether the vehicle is near a corner, whether an object is near the goal, or whether the vehicle is near the goal.
It will finally execute the setStateLaneKeeping action. The sequence will stop if any child fails.

Then, the lane-change fallback will try the left lane-change decision sequence. If that sequence fails, it will
try the right lane-change decision sequence. If that sequence fails, the fallback will fail.

Next, the left lane-change decision sequence will check whether a left lane change is profitable. If the condition
succeeds, it will execute the left lane-change option fallback. It will stop if any child fails.

Then, the left lane-change option fallback will try the left-blockage sequence. If that sequence fails, it will
try the left-lane-change execution sequence. If that sequence fails, it will execute the setStateLaneKeeping
action.

Next, the left-blockage sequence will execute the fallback that checks for a static object in the left lane or an
irregularity on the left side. It will then execute the setStateLaneKeeping action. The sequence will stop if any
child fails.

Then, the left-lane-change execution sequence will check whether the left lane is changeable. It will then
generate a left lane-change path. It will next execute the left-lane safety fallback. The sequence will stop if
any child fails.

Next, the right lane-change decision sequence will check whether a right lane change is profitable. If the
condition succeeds, it will execute the right lane-change option fallback. It will stop if any child fails.

Then, the right lane-change option fallback will try the right-blockage sequence. If that sequence fails, it will
try the right-lane-change execution sequence. If that sequence fails, it will execute the setStateLaneKeeping
action.

Next, the right-blockage sequence will execute the fallback that checks for a static object in the right lane or
an irregularity on the right side. It will then execute the setStateLaneKeeping action. The sequence will stop if
any child fails.

Then, the right-lane-change execution sequence will check whether the right lane is changeable. It will then
generate a right lane-change path. It will next execute the right-lane safety fallback. The sequence will stop if
any child fails.

Next, the mandatory-lane-change fallback will check whether a lane change is mandatory. If the condition succeeds,
the fallback will succeed. If the condition fails, the AlwaysSuccess node will succeed.

Then, the LaneChangeLeft sequence will check whether left-lane-change mode is active. If the condition succeeds,
it will execute the lane-change completion fallback. The sequence will stop if either child fails.

Next, the left lane-change completion fallback will try the sequence that checks whether the lane change has
ended, sets lane-keeping mode, and calls the global-path action. If that sequence fails, it will execute the
speedProfileLaneChange action.

Then, the LaneChangeRigth sequence will check whether right-lane-change mode is active. If the condition succeeds,
it will execute the right lane-change completion fallback. The sequence will stop if either child fails.

Next, the right lane-change completion fallback will try the sequence that checks whether the lane change has
ended, sets lane-keeping mode, and calls the global-path action. If that sequence fails, it will execute the
speedProfileLaneChange action.

Then, the Recovery sequence will execute the setStateLaneKeeping action.

Next, the traffic-check fallback will check whether traffic can be passed at the traffic light. If the condition
fails, it will execute the stopTrafficLight action.

Then, the unprotected-turn fallback will try the sequence that checks whether an unprotected turn exists, checks
whether it is impassable, and executes the stop action. If that sequence fails, the AlwaysSuccess node will
succeed.

Next, it will execute the setPath action after the path-generation sequence succeeds. It will then execute the
publishData action. The sequence will stop if either action fails.

Then, the mission-state fallback will try the sequence that checks whether the goal has been reached, sets the
mission state to arrived, and publishes the mission state. If that sequence fails, it will execute the
setStateMissionGoing action. If neither sequence succeeds, the fallback will fail.
