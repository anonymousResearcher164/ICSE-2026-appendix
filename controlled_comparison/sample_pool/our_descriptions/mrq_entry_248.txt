The mission describes navigation to a goal with path replanning and recovery.

First, the root recovery node NavigateRecovery will execute the main action NavigateWithReplanning. The robot will
execute the recovery action RecoveryFallback if the main action fails. It will retry the main action after recovery
and stop when six recovery attempts are exhausted.

Next, the PipelineSequence NavigateWithReplanning will execute the actions RateController and FollowPath in order.
It will advance to the next action while the current action is running or has succeeded. It will stop if an action
fails.

Then, the ROS action RateController will execute the recovery node ComputePathToPose at a rate of 1.0 hertz.

After that, the recovery node ComputePathToPose will execute the ROS action ComputePathToPose. If the action fails,
it will execute the ROS action ClearEntireCostmap named ClearGlobalCostmap-Context. It will retry the path
computation after recovery and stop after one retry.

Next, the recovery node FollowPath will execute the ROS action FollowPath. If the action fails, it will execute the
ROS action ClearEntireCostmap named ClearLocalCostmap-Context. It will retry path following after recovery and stop
after one retry.

Then, the ReactiveFallback RecoveryFallback will execute the ROS action GoalUpdated first. If GoalUpdated succeeds,
it will stop the recovery fallback. If GoalUpdated fails, it will execute the recovery action RecoveryActions. It
will re-evaluate GoalUpdated while the recovery action is running and stop the recovery action if GoalUpdated
succeeds.

Finally, the SequenceStar RecoveryActions will execute the actions ClearLocalCostmap-Subtree,
ClearGlobalCostmap-Subtree, Spin, and Wait in order. If an action succeeds, it will remember that action and move
to the next action. If an action fails, it will restart from the failed action.

Parameters: The ROS action RateController will use the literal hz value 1.0. The ROS action ComputePathToPose will
read the goal from blackboard key {goal}, store the path under blackboard key {path}, and use the literal
planner_id value GridBased. The ROS action ClearEntireCostmap named ClearGlobalCostmap-Context will use the literal
service_name value global_costmap/clear_entirely_global_costmap. The ROS action FollowPath will read the path from
blackboard key {path} and use the literal controller_id value FollowPath. The ROS action ClearEntireCostmap named
ClearLocalCostmap-Context will use the literal service_name value local_costmap/clear_entirely_local_costmap. The
ROS action ClearEntireCostmap named ClearLocalCostmap-Subtree will use the literal service_name value
local_costmap/clear_entirely_local_costmap. The ROS action ClearEntireCostmap named ClearGlobalCostmap-Subtree will
use the literal service_name value global_costmap/clear_entirely_global_costmap. The ROS action Spin will use the
literal spin_dist value 1.57. The ROS action Wait will use the literal wait_duration value 5.
