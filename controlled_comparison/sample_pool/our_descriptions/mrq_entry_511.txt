The mission describes navigating the robot to a goal while computing and following a path, replanning when
necessary, and recovering from navigation failures.

First, the robot will execute the main navigation sequence NavigateWithReplanning. If this sequence fails, it will
execute the recovery fallback RecoveryFallback. After recovery, it will retry the main navigation sequence. If
recovery fails and two retries are exhausted, it will stop execution.

Next, it will execute the actions RateController and FollowPath in order. While an action is running or has
succeeded, it will proceed to the next action. If an action fails, it will stop the sequence.

Then, it will execute ROS action RateController around the recovery node ComputePathToPose.

Next, it will execute the main ROS action ComputePathToPose. If this action fails, it will execute the recovery
fallback PathToPoseFallback. After recovery, it will retry the main action. If recovery fails and four retries are
exhausted, it will stop execution.

Then, it will execute the actions GoalUpdated and GlobalPlannerRecoveryActions in order. If GoalUpdated succeeds,
it will stop the fallback. Otherwise, it will execute GlobalPlannerRecoveryActions. While a later action is
running, it will re-evaluate GoalUpdated. If GoalUpdated succeeds during this evaluation, it will halt the running
action and stop the fallback.

Next, it will execute the recovery actions ClearGlobalCostmap-Context and Wait consecutively. If
ClearGlobalCostmap-Context fails, it will move to Wait. If Wait also fails, the recovery action will fail.

Then, it will execute the main ROS action FollowPath. If this action fails, it will execute the recovery fallback
FollowPathFallback. After recovery, it will retry the main action. If recovery fails and four retries are
exhausted, it will stop execution.

Next, it will execute the actions GoalUpdated and PlannerRecoveryActions in order. If GoalUpdated succeeds, it
will stop the fallback. Otherwise, it will execute PlannerRecoveryActions. While a later action is running, it
will re-evaluate GoalUpdated. If GoalUpdated succeeds during this evaluation, it will halt the running action and
stop the fallback.

Finally, it will execute the recovery actions ClearLocalCostmap-Context and Spin consecutively. If
ClearLocalCostmap-Context fails, it will move to Spin. If Spin also fails, the recovery action will fail.

Parameters: ROS action ComputePathToPose will read {goal} as its goal. ROS action ComputePathToPose will store its
computed path under {path}. ROS action ComputePathToPose will use GridBased as its planner_id.
