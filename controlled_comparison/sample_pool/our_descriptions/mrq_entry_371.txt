The mission describes a repeated sequence that checks LTL state, handles replanning, selects an action, and
updates the LTL state.

First, the robot will execute the contained sequence {num_cycles} times.

Next, it will execute the first fallback, the reactive sequence, and UpdateLTL in order. It will stop the sequence
if any action fails.

Next, it will execute LTLPreCheck and then the first ForceFailure consecutively. If LTLPreCheck fails, it will
move to the first ForceFailure. If no action succeeds, the fallback will fail.

Next, it will check whether LTLPreCheck is true for ltl_state_current {ltl_state_current},
ltl_state_desired_sequence {ltl_state_desired_sequence}, and ltl_state_executed_sequence
{ltl_state_executed_sequence}.

Next, it will execute ReplanningRequestLevel2 and make sure it always fails.

Next, it will execute the reactive sequence in order. If an action fails, it will stop execution. While a later
action is running, it will re-evaluate the previous actions. If a previous action fails, it will halt the running
action and stop the sequence.

Next, it will execute the first fallback and then the second fallback in order. If an action succeeds, it will
stop execution. Otherwise, it will continue to the next action.

Next, it will execute FakeDetectionLevel1 and then the second ForceFailure consecutively. If FakeDetectionLevel1
fails, it will move to the second ForceFailure. If no action succeeds, the fallback will fail.

Next, it will execute the second ForceFailure and make sure it always fails.

Next, it will execute ReplanningRequestLevel1 and make sure it always fails.

Next, it will execute ReactiveLTLStateCheck and then the third ForceFailure consecutively. If
ReactiveLTLStateCheck fails, it will move to the third ForceFailure. If no action succeeds, the fallback will fail.

Next, it will check whether ReactiveLTLStateCheck is true for ltl_state_current {ltl_state_current} and
ltl_state_desired_sequence {ltl_state_desired_sequence}.

Next, it will execute ReplanningRequestLevel2 and make sure it always fails.

Next, it will execute FakeDetectionLevel3 and then the fourth ForceFailure consecutively. If FakeDetectionLevel3
fails, it will move to the fourth ForceFailure. If no action succeeds, the fallback will fail.

Next, it will execute ReplanningRequestLevel3 and make sure it always fails.

Next, it will execute the fourth fallback and then the fifth ForceFailure consecutively. If an action succeeds, it
will stop execution. Otherwise, it will continue to the next action. If no action succeeds, the fallback will fail.

Next, it will execute Switch4. If bt_action_type {bt_action_type} matches move, it will execute MoveAction. If it
matches stay, it will execute StayAction. If it matches start_training, it will execute GuideAction. If it matches
terminate_training, it will execute BackNormalAction. If no case matches, it will execute AlwaysFailure.

Next, it will execute ReplanningRequestLevel3 and make sure it always fails.

Next, it will execute UpdateLTL.

Parameters: ReplanningRequestLevel2 will read ltl_state_current from {ltl_state_current}, read and update
ltl_state_executed_sequence under {ltl_state_executed_sequence}, and read and update replanning_request under
{replanning_request}.

ReplanningRequestLevel1 will read ltl_state_current from {ltl_state_current}, read and update
ltl_state_executed_sequence under {ltl_state_executed_sequence}, and read and update replanning_request under
{replanning_request}.

FakeDetectionLevel1 will read replanning_fake_input from {replanning_fake_input}.

FakeDetectionLevel3 will read replanning_fake_input from {replanning_fake_input}.

MoveAction will read bt_action_type from {bt_action_type}, read current_action from {current_action}, store
goal_sent under {goal_sent}, read move_base_finished from {move_base_finished}, and read move_base_idle from
{move_base_idle}.

StayAction will read bt_action_type from {bt_action_type}, read current_action from {current_action}, and read and
update ltl_state_current under {ltl_state_current}.

GuideAction will read bt_action_type from {bt_action_type}, read current_action from {current_action}, and read
and update ltl_state_current under {ltl_state_current}.

BackNormalAction will read bt_action_type from {bt_action_type}, read current_action from {current_action}, and
read and update ltl_state_current under {ltl_state_current}.

UpdateLTL will read and update action_sequence under {action_sequence}, read and update action_sequence_executed
under {action_sequence_executed}, store bt_action_type under {bt_action_type}, store current_action under
{current_action}, and read and update ltl_state_desired_sequence under {ltl_state_desired_sequence}.
