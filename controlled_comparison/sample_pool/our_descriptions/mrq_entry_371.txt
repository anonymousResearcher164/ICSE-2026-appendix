The mission describes repeated evaluation of LTL states, replanning requests, and selected robot actions.

First, the robot will execute the sequence {num_cycles} times.

Next, it will execute the pre-check, reactive decision process, and LTL update in order and stop the sequence if
any action fails.

First, it will check whether LTLPreCheck matches the current LTL state, desired LTL state sequence, and executed
LTL state sequence. If LTLPreCheck fails, it will execute ReplanningRequestLevel2 and force that recovery branch to
fail.

Next, it will execute the reactive sequence in order. While a child is running, it will re-evaluate the preceding
children. If a preceding child fails, it will halt the running child and stop the reactive sequence.

First, it will execute FakeDetectionLevel1. If FakeDetectionLevel1 fails, it will execute ReplanningRequestLevel1
and force that recovery branch to fail.

Next, it will check whether ReactiveLTLStateCheck matches the current LTL state and desired LTL state sequence. If
the check fails, it will execute ReplanningRequestLevel2 and force that recovery branch to fail.

Next, it will execute FakeDetectionLevel3. If FakeDetectionLevel3 fails, it will execute ReplanningRequestLevel3
and force that recovery branch to fail.

Next, it will read {bt_action_type} and compare it with the cases move, stay, start_training, and
terminate_training. If the value is move, it will execute MoveAction. If the value is stay, it will execute
StayAction. If the value is start_training, it will execute GuideAction. If the value is terminate_training, it
will execute BackNormalAction. If no case matches, it will execute the default failure branch. If the selected
action fails, it will execute ReplanningRequestLevel3 and force that recovery branch to fail.

Finally, it will execute UpdateLTL after the reactive sequence.

Parameters: ReplanningRequestLevel2 will use {ltl_state_current}, update {ltl_state_executed_sequence}, and update
{replanning_request}. FakeDetectionLevel1 will use {replanning_fake_input}. ReplanningRequestLevel1 will use
{ltl_state_current}, update {ltl_state_executed_sequence}, and update {replanning_request}. ReactiveLTLStateCheck
will use {ltl_state_current} and {ltl_state_desired_sequence}. FakeDetectionLevel3 will use
{replanning_fake_input}. MoveAction will use {bt_action_type}, {current_action}, update {goal_sent},
{move_base_finished}, and {move_base_idle}. StayAction will use {bt_action_type}, {current_action}, and update
{ltl_state_current}. GuideAction will use {bt_action_type}, {current_action}, and update {ltl_state_current}.
BackNormalAction will use {bt_action_type}, {current_action}, and update {ltl_state_current}.
ReplanningRequestLevel3 will use {ltl_state_current}, update {ltl_state_executed_sequence}, and update
{replanning_request}. UpdateLTL will update {action_sequence}, update {action_sequence_executed}, update
{bt_action_type}, update {current_action}, and update {ltl_state_desired_sequence}.
